## 示例 A：一句话需求 → PPT 汇报提示词

### A.1 用户原始输入

> "帮我做个季度规划的 PPT，讲 chatbi 的自动化任务"

### A.2 补全槽位

| 槽位 | 判断 | 依据 |
|---|---|---|
| 文档类型 | PPT（`.pptx`） | 用户说"PPT" |
| 场景 | 季度规划汇报 | 用户说"季度规划" |
| 产品域 | AGT（智能问数） | 主题是 ChatBI |
| 主题 | 自动化任务本季度的建设节奏与版本落点 | 推断，列待确认 |
| 受众 | 产品/研发管理层（评审会） | 季度规划默认场景 |
| 口径 | **待确认，默认内部评审** | 规划含版本与资源，默认不外发 |
| 篇幅 | 15–20 页 / 20 分钟 | 规范页默认 |
| 已有素材 | 无 → 待确认"是否已有本季度版本清单" | — |

> 追问策略：主题与版本清单两个问题最关键，**合并成一次问完**；其余用假设 + 待确认。若用户没回，也可先按"假设"出提示词。

### A.3 优化后的提示词

```text
# 角色
你是浩鲸科技 BI 产品团队的智能问数（ChatBI）产品负责人，擅长把复杂的技术演进压缩成「一页一个结论」的管理层汇报材料。

# 任务
产出一份《ChatBI 自动化任务 · Q4 季度规划汇报》PPT（季度规划汇报场景）。
核心目标：让管理层认可「本季度把自动化任务从『定时触发 demo』推进到『可运维的主动服务』」这一条主线，并明确版本落点与资源诉求。
不做：不铺开讲 ChatBI 全部能力，不写竞品长篇分析（最多 1 页对标）。

# 知识库依据（已核实，不得替换为自行编造的内容）
1. `wiki/deliverables/roadmap/chatbi-自动化任务-演进研究.md` — D2.0.2 设计基线：定时触发 + 动态结果生成 + 灵活…；本期设计约束：定时任务对标 Codex 自动化任务模式；结果仅向创建人分发；失败达阈值熔断且不通知；结果保留 180 天（【已验证】，2026-10-14）。
2. 同页 §业界对标三/四 — 帆软「预警处理中心」是最完整的结果闭环参照；Tableau 的「指标目标触发」把触发源归属之争摆上台面（【推断】，2026-10）。
3. `wiki/concepts/主动式数据服务.md` — 任务视角下"没被建任务的指标等于没被监控"；指标视角把监控下沉到语义层，语义层建到哪里，监控就覆盖到哪里（【推断】，2026-10-10）。
4. `wiki/concepts/Headless执行契约.md` — 无人值守场景"一次执行到底算成功还是失败"必须由契约约定，这是从 demo 走向可运维的分水岭（【已验证】）。
5. `wiki/entities/ChatBI智能问数系统.md` §三 — 我方最大差距是评测运营而非模型能力；指标异动分析已有实现（`ChatIndicatorService` + 4 张表）但未产品化（【已验证】，2026-10-19，内部口径）。
事实规则：只用以上依据 + 用户提供的版本清单；缺依据的结论标【待验证】并列入"待确认"；数字带出处与日期；竞品只用官方公开材料。

# 输出规格
- 格式：`.pptx`；母版 `wiki/templates/浩鲸科技_20周年_ppt中文模板_白.potx`（只读，另存）。
- 规范页：`wiki/templates/ppt-演示文稿写作模板.md`（页类型 §二、版式选用 §三、场景页序 §六、自检清单 §八）。
- 页序（季度规划汇报）：封面 → 目录 → 上期回顾(1–2) → 本期目标(1) → 重点战役(3–4) → 版本/里程碑路线图(1–2) → 资源与依赖(1) → 风险(1) → 总结与下一步(1) → 附录。
- 页数：15–20 页；20 分钟汇报节奏。
- 命名：`YYYYMMDD-chatbi-自动化任务-Q4规划-V0.9.pptx`（定稿才 V1.0）。

# 受众与口径
- 受众：产品负责人 + 研发负责人 + 交付负责人；评审会现场。
- 口径：`内部`（可讲实现与缺口）；但**第 1 页与总结页若有可能外传，按外发标准写**——隐去 Hermes 等底层框架名，统一"自研 Agent 引擎"。
- 两页红线：1) 隐去技术名 ≠ 改称不实能力；2) 竞品对比只写官方公开材料，保留出处。

# 写作与证据规范
- 每页标题必须是结论句（如"本期只做三件事：闭环、可运维、可度量"，而不是"本期目标"）。
- 一页一个观点；正文 ≤6 行、每行 ≤2 分句；图 > 表 > 字。
- 用母版版式（按正文占位符数量选：观点/结论=×1，对比=×2，三要点=×3）；不手工堆文本框。
- 主色 ≤2 个（accent4 #0082FF 为主）；同一指标跨页同色；关键数字用强调色，一页只强调一个点。
- 图表脚注必须含：口径、单位、来源、日期。

# 验收清单（交付前逐项自查）
- [ ] 每页标题都是结论句
- [ ] 每页只有一个中心论点，正文 ≤6 行
- [ ] 使用母版版式、页码正常
- [ ] 字体为主题字体（Roboto / 方正兰亭细黑简体）
- [ ] 主色 ≤2，强调色只标一个点，同指标跨页同色
- [ ] 图表有标题/单位/口径/来源/日期
- [ ] 涨跌/正负配色已显式标注
- [ ] 口径合规：外传风险页已脱敏且未改称不实归属
- [ ] 总结页含"下一步动作 + 负责方 + 时间"
- [ ] 页数与 20 分钟汇报匹配
- [ ] 命名符合 `YYYYMMDD-<产品>-<主题>-<版本>.pptx`

# 未决问题（无法从依据确定时列这里，不要猜）
1. 本季度具体版本清单与里程碑日期 —— 影响"版本/里程碑路线图"页；确认方式：给我一句话版本-需求对应关系即可。
2. 是否已有资源诉求（人力/依赖团队）—— 影响"资源与依赖"页。
3. 汇报是否可以出现客户名 —— 影响口径（默认不出现）。

# 交付方式
1. 先输出 15–20 页的**页面大纲**（每页一句结论），确认后填充内容；
2. 套母版生成 PPTX；3. 跑自检清单；4. 汇报：完成项 / 未决项 / 口径说明。
```

### A.4 优化点（相对原句）

- 我方定位必须写推定依据（"按语义层形态 + 官方限制清单推定"），不要写成定论。
- 结尾"来源"小节列 wiki 页 + raw 素材路径。

### C.4 优化点

- 把"写个研究"从**资料汇编**改成**回答一个判断问题**（程度差异 vs 路线差异）；
- 强制标注**推定依据**与置信度，避免把竞品定位写成事实；
- 用五层级作为统一标尺，让对比可复核；
- 加"我方风险"章节，防止研究变成自我表扬；
- 明确"内部/禁止外发"，避免竞品对照外泄。

## 附：三个示例的共同点（可复用的检查项）

1. 都有一个**可判断的核心命题**（不是"写一份 XX"）。
2. 都从知识库取了 **3–5 条可引用依据**，并标了置信度与日期。
3. 都把**规范页 + 母版绝对路径 + 场景骨架 + 篇幅 + 命名**写死。
4. 都显式写了**口径与红线**。
5. 都给了**验收清单**与**未决问题**。
6. 都规定了**交付顺序**（先大纲/结论 → 再全文 → 再导出）。
